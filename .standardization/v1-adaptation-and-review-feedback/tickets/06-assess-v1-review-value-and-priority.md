# Assess v1 review value and priority

Type: research
Phase: assessment
Status: resolved
Claimed by: /root
Blocked by:

## Question

Would excluding review interactions that Web Editor Revisions v1 cannot represent—especially atomic multi-paragraph paste, cross-paragraph or multi-range deletion, proposal grouping or hierarchy, and material reshaping of an already pending proposal—reduce the standard to little or no user value? Establish a bounded priority scale that distinguishes capabilities necessary for any credible review method, high-priority gaps that limit a general-purpose review-mode claim, useful but non-foundational review facilities, and product workflow concerns. Rank only where representative product convergence, review-safety reasoning, and the released v1 semantics support the rank; label direct user-preference uncertainty rather than inventing prevalence. Stop when the scale can determine what v1 may credibly claim now and which missing semantics should be prioritized separately.

## Resolution

Resolved by [V1 review value and capability priority](../evidence/06-v1-review-value-and-priority.md).

Version 1 retains material value as a bounded portability and review-integrity standard: it defines stable proposal identity, exact payload and attachment, accepted and rejected projections, atomic resolution, deterministic successor remapping, truthful loss reporting, and a useful paragraph-local plus single-boundary proposal subset. Those guarantees are not supplied merely by an editor showing tracked changes.

The missing broad and compound interactions nevertheless have high priority for a general-purpose document review-mode claim because structural paste, cross-paragraph deletion, native suggestion joining, and hierarchical or multi-range changes occur in representative systems. Their absence means implementations must split, materialize, refuse, or report loss for ordinary edits. It therefore limits v1's coverage and positioning, rather than making its core valueless.

The evidence supports four priority bands: critical review integrity; high-priority practical coverage; useful review operation and triage; and product-specific workflow. V1 covers most critical semantic integrity for its supported subset, needs an informative clarification about scope and atomicity, and lacks several high-priority practical-coverage semantics. Partial acceptance inside every broad proposal is not yet established as universally high priority. Comments, permissions, approval gates, and a prescribed UI remain separable product-workflow concerns.
